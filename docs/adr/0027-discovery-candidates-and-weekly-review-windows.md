# 发现方向与每周回顾的冻结身份

自动知识文章把 DiscoveryBatch、TopicCandidate、KnowledgeArticle 和 GenerationRun 分开。发现输入的哈希不包含可变历史文章摘要，重复调度复用同批发现；候选问题有独立方向哈希与唯一文章关联。成稿前重新召回相关历史方向和核查来源策略，避免队列等待期间新增文章导致重复付费。旧文章映射到 legacy 批次与一个方向，不能补造曾经没有执行的选材判断。

新材料来自持久学习变更序列，游标与文章接纳在同一事务推进。历史探索可主动按游标分页。材料是完整的、真实可用的笔记与重点；召回上限20项、40KB，先预留不同来源的空间。程序记录容量排除，模型记录采用/舍弃和支持/补充/反方；模型漏报未采用项只标“未说明”，不能补造判断。模型省略采用依据或虚构身份仍失败。

回顾使用 Owner 的 IANA 时区确定当地周一到下一周一的窗口，而不是固定168小时，覆盖夏令时。批次按 profile 与当地周起始日期幂等，冻结 UTC 边界、时区、材料和模型。设置只影响未来接纳；文章和回顾开关相互独立。问题依据与 Owner 回答分开保存，回答有自己的版本和自评，显式保存才生成个人笔记。

两条流程共用已有 Provider 文本运输和队列的断点/用量边界，领域验证仍由各自 Store 操作承担，没有另建通用 Agent 框架。新契约使用 knowledge-article-v3，保留 v1/v2 冻结任务解释；每次远端开始先持久记录，已知响应先保存断点和费用再提交业务结果。重试已知合法断点不重放；未知结果须显式重试，旧 receipt 与远端标记保留。来源策略撤销后也不能丢掉已知付费响应的用量。
