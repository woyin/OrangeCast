## 3. 关键实现约定

### 3.1 S07：质量准入与性能

继承的 2026-10-01 最大 2048 维结果：1 万窗口冷 p95 611.7ms，5 万冷 p95 1823ms，均未达 150/500ms；热 p95 分别 87.86/445.1ms。这些不是本次新测数据，也不能用热结果替代冷准入。

先区分 SQL 读取、向量解码、临时分配、权限/版本检查和点积成本，再选择优化；保持来源授权与索引身份检查。比较同维数/同语料/同机的冷热测试，报告采样 heap 与准确 RSS/峰值的区别。不得以降维、缩小规模、预热、排除慢样本或改阈值制造通过。

报告至少冻结：query/relevance manifest 哈希、来源范围与版本、索引配置/事件版本、embedding 连接指纹/模型/维数、融合规则、估价/实际费用、源码与机器/测试方法。配置、材料或索引相关身份变化使旧准入失效。真实 Recall@10 不低于 FTS；改写子集目标提高 10 个百分点。缺真实配置/有效报告或指标未通过时语义保持关闭，FTS 可正常工作。

工程收口可以证明“有效报告才可开启、失败/缺报告默认关闭”并登记外部质量待验；**不能据此宣称语义收益已通过或打开生产开关**。C09/G/U 的本地/FTS 路径继续推进，真实收益不阻塞这些独立工作。

### 3.2 C08：旧单来源持久适配

当前 `QuestionStudyJobInput` 是 `question-study-task-v1`，且现有入队验证限定 `pod`；旧 `StudyChatProvider` 接口缺调用 context/实际 usage 返回，旧客户端仍等待同步回答。因此不能简单将旧接口的函数名改为新 Worker 后宣布迁移完成。

实施一个单来源持久适配器，复用生成/检查的调用边界、checkpoint、receipt、预算和控制纪律，保留各自业务校验/采用事务。沿用并冻结实际旧 QA Provider/模型选择；不能静默更换为 POD 或冒用新问题对话的模型。若旧 Provider 无准确用量契约，扩展其适配接口并回归既有调用方；未知费用保留未知，不计零。

保留旧 POST 与历史读取地址；新命令返回任务/轮/会话身份（成功入队建议 202，最终响应结构以实现测试冻结），只读状态入口由播放器轮询。requestKey 在提交前保存，响应丢失用原身份查询/核对；无幂等身份旧客户端给明确兼容反馈，不隐藏重发。旧历史继续可读，不自动重发给供应商，不补造新的冻结依据/usage。

保持生成有真实 Reference、检查 Related 通过才可展示的旧纪律。付费响应先持久化并记账，提交时复查来源权限、版本与运行控制。新接受回答与轮状态在同一事务；停止/删除先提交，迟到正文不得附着，数字用量保留。新适配不能为旧会话伪造一个 Owner 学习问题。

### 3.3 G/U：原音与个人理解的身份

区间使用 snapshot + 真实片段/起止 + audioSHA，进度使用区间身份；笔记锚点保留绝对音频位置，整集/DJ/补听不得共享错误进度。

理解快照拥有独立不可变版本与当前指针；无来源的个人想法可保存。引用来源及正文类别保持真实，不制造跨来源 Citation。模型选材需要理解自身策略与所有引用来源同时允许；默认 local_only。来源清理移除参考正文及失效派生索引，保留 Owner 答案并明确引用已失效。

### 3.4 W/F：自动文章与反馈

四用途为默认综合、知识解释、观点对比、实践指南。用途和规则版本冻结到全部阶段及估价；默认不暂停，保持已有自动成文行为。只有用户开启计划预览时，选材后等待确切计划确认；确认与写作入队/预算准入必须原子去重。

反馈锚定确切段落/版本；反馈、接纳案例、写作偏好是三个不同动作。只有明确接纳的案例进入评测，模型原因不直接变成事实分类。用途变更保留旧通过版，不能冒充知识增量；报告不自动调整生产模型或提示。

### 3.5 E/O：成果包、离线包与备份

| 项目 | 内容与边界 | 恢复/清理 |
| --- | --- | --- |
| 成果包 | Markdown/ZIP，500 对象/100MiB；默认通过版，历史/草稿明确选择 | 私有文件 0600，24 小时过期；源状态变化失效，可无模型重建 |
| 离线包 | 本地 EvidenceAudio 原音与选定内容，10 来源/500MiB；不含远端原音、DJ 解说或私人录音 | 完整验证后可用，默认授权 24 小时；登录/设备 namespace 隔离，退出清理 |
| 实例备份 | 沿用既有 v2 的数据库和应保留服务器私有文件 | 不包含临时 ZIP 或浏览器下载音频；真实升级/恢复另验 |

离线只缓存版本化外壳与明确投影，不缓存动态 SSR、登录、设置、任务或 CSRF。outbox 只接受文字笔记/整理草稿及原音进度，不接受生成/转写/任务控制/预算变更。回网先验证授权/撤回，再显示或同步；每条合法写入与 UUID/hash 回执原子提交，ack 前保留客户端文字。

真实断网时无法实时感知服务器撤回：用期限、回网优先核验和明确提示处理，不承诺即时远程删除。SW 更新不能强制刷新在途播放、录音或同步；清理下载不能清理未同步草稿。

## 5. 验证与故障处理规则

### 5.1 按行为收口，不在每次修改后重跑整库

1. 子任务修改后先跑真实命中的针对测试。持久事务/并发必须 race；前端要执行实际脚本，不能只语法检查或测试镜像逻辑。测试文件/名称尚未存在时不得当作通过；匹配为空必须报未覆盖。
2. 每个数据任务同时覆盖新增迁移、旧行读取、来源归档/撤权/清理、备份恢复及晚到响应，不把这些统一推迟至 V01。
3. 每阶段浏览器使用独立库/目录与确定性供应商；核对真实 DOM、根 audio、任务、usage、引用身份及文件内容，截图必须查看。实际网络行为只模拟本地桩，不能冒称真实模型或手机。
4. 阶段产出已获相关证据且无已知重大问题后进入下一卡；新变更/失败才重复受影响检查。技术已完成但真实资料待验不会阻塞无依赖工作。
5. V03 在完整候选源码执行最终全量门禁。覆盖率规则维持 95%，原 store 78.4/server 79.4 地板及原豁免不降低、不增加。

```sh
make test
make cover-gate
make lint
go vet ./...
go build ./cmd/cloudwisepod
# 对本次实际存在的全部 .js 文件逐个执行 node --check
git diff --check
```

不能因旧 race 通过而推断最终覆盖率或完整旅程通过。V04 纯文档修改只核对链接/实际实现，不无理由再次跑全部源码测试。

### 5.2 必测的事务/费用竞争

| 场景 | 预期 |
| --- | --- |
| 同 UUID/同负载并发或响应丢失重放 | 同一任务/业务写入、唯一 receipt |
| 同 UUID/不同负载 | 409，不静默修改原任务 |
| 父版本/范围/用途/来源或权限改变 | 原输入不重写；明确冲突/失效，需要新命令 |
| 远端已知响应、记账或采用失败 | checkpoint 恢复，零供应商重发，继续复查权限 |
| 外发后响应未知 | 保留 unknown；只有明确新 attempt 可付费重发 |
| 停止/清理已提交后晚到结果 | 不采用正文，不重附着已清理快照；保留数字用量 |
| 离线写入成功但 ack 丢失 | 重同步只返回同回执，不产生第二条笔记 |
| 导出完成前来源状态变化 | 文件不发布/下载失效，不能绕过预览范围 |
| SW/Cache 不完整、驱逐或配额故障 | 不标 ready；旧可用包与未同步草稿保持可核对 |

### 5.3 提交和继续执行

每次提交保持可工作的有界行为；schema/后端先提交时未完成 UI 不启用。每卡收口立即更新主任务清单和实施记录；阶段状态汇报不是撤销已有开发授权，不把普通完成汇报视为停止剩余任务的理由。

跨轮继续时读取最新 HEAD、工作树、任务状态与实施记录，只完成未闭合项；已经有适用证据的行为不重新从头开发。出现真实外部阻断，登记具体缺口，完成所有独立工程工作；只有确需外部信息的分支等待。不得以等待个人笔记或手机为由停下 47 项的工程实施。
