# 自动知识文章开发计划

日期：2026-09-30。依据：用户授权“制定详细的开发计划，然后根据开发计划进行开发”。目标是个人听学与自动成稿并重。

## 交付行为

Owner 可以立即从已有重点和笔记生成文章，也可以一次开启后台自动生成。后台依次发现选题、写作、独立审校，必要时最多修订一次。成稿显示来源、AI 综合和个人笔记身份，可阅读和下载 Markdown。未通过审校、素材不足、配置缺失、任务失败都有明确状态。

自动知识文章是学习成果的整理与综合，不自动承担 OwnerClaim。现有主张确认、Brief、ArticleRevision 和发布包流程继续工作。自动文章单独保存，但共用 SQLite、Provider、持久队列、用量、预算、来源快照与备份。

## 默认规则与实现边界

- 自动化默认关闭，立即生成可直接使用；用户在文章页开启后后台周期检查。无凭据不发起调用。
- 默认每画像每天最多一篇、素材更新防抖 30 分钟；立即生成不受防抖影响，但仍遵守预算与在途背压。
- 初次扫描存量材料，之后以有界材料快照的内容指纹判断变化，不要求新增 6 条或跨两集。相同材料不因调度重复而重新收费。
- 单次仅选择一个材料充分的方向，保存若干候选供查看；历史生成文章及既有创作历史参与去重。
- POD_* 独立于数据库 Groq/OpenAI 密钥和模型配置，当前自动文章使用这一组连接；任务冻结模型名与提示词版本，密钥只在进程配置中使用。
- 来源摘录与个人反思分开。文章采用结构化段落并挂材料 ID，来源链接由程序生成，模型不得编造链接。
- 每次远端请求独立记账；未知费用显示未知，已有月预算配置时未登记价格明确阻断。
- 不新增联网研究、第三方同步或自动发布。材料不足可等待新学习成果。

## 进度

P1–P6 已完成。实现及验收记录见 [验收报告](2026-09-30-automatic-knowledge-articles-validation.md)。

## 任务依赖与最终落点

1. 先建立配置边界和领域契约，明确自动知识文章不自动确认 OwnerClaim。对应 `internal/config/environment.go`、`internal/provider/knowledge_article.go` 和 ADR-0025。
2. 新增迁移 0056，形成设置、文章状态和输入指纹的持久化基础。通过 Store 收集与冻结材料，复用来源快照、证据和权限判断；队列任务只保存配置身份，不保存密钥。
3. 实现 Discover → Write → Review；审校失败则 Revise → ReviewFinal。每次提交把文章状态、模型结果与下一任务置于同一个 SQLite 事务；中断后复用 checkpoint。
4. 在现有 Worker 中接入预算、用量、调用边界和失败收尾。已持久响应不重复收费；未知响应不自动重放；显式重试保留旧审计记录。
5. 增加后台周期扫描和手动入口，再提供列表、偏好、详情、依据、失败重试与 Markdown 下载。复用认证和 CSRF，不从页面 GET 触发模型。
6. 验证阶段覆盖完整旅程、失败恢复、并发幂等、预算、权限、迁移、备份恢复和删除传播，然后执行项目门禁、浏览器与真实端点检查。

## 启用与运维

- 部署前使用现有备份命令保存数据库；新版本启动自动应用迁移 0056。回退到旧版本前应恢复迁移前备份，不把旧程序直接指向新 schema。
- 从项目根目录启动或重启服务，读取已有 `.env` 中完整的 `POD_*`。进程环境变量优先；不执行环境文件中的 shell 指令。
- 访问“知识文章”，可以立即生成；在“自动生成与文章偏好”开启后台生成并设置读者、风格、等待时间和每日上限。
- 默认关闭自动生成，每日自动准入上限为 1，防抖 30 分钟；人工立即生成和人工重试不计入这个自动准入上限，但仍接受预算和在途限制。
- 有月预算时，先在内容工作台登记 `pod` 与 `POD_MODEL` 对应的价格。模型未返回用量或未登记价格时，不把未知费用显示成免费。
- 暂停后台生成只停止接纳新的自动文章，已入队阶段继续完成。失败需显式重试；素材不足或最终审校未通过的文章保留判断和反馈，等待材料变化后生成新文章。

## 实际限制

当前从最多 40 条重点、40 条笔记收集候选，再限制完整材料 JSON 为 40 KB、历史为 8 KB；单次选择一个最充分的方向。相同输入指纹不会重复生成，更新材料、读者、风格或模型可产生新输入。这个版本不会一次消耗整个知识库，也不会自动发布。

结构化引用验证可以确认材料身份、证据存在与段落归因，语义是否充分支持正文仍依靠独立模型审校与后续人工阅读。真实接口测试使用合成材料，不能替代用户资料的内容质量验收。
