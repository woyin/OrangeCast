用户已接受本轮全部功能与实现建议，后续指令已授权完成全部开发。实施与验证按末尾进度逐项记录，不以计划代替验收。第一轮自动文章实现及证据见 [开发计划](2026-09-30-automatic-knowledge-articles.md) 和 [验收报告](2026-09-30-automatic-knowledge-articles-validation.md)。

## 1. 交付目标与覆盖范围

个人日常流程：打开首页继续听 → 随听记录来源与个人理解 → 搜索、回顾笔记 → 自动形成有依据的文章 → 必要时修改并再审 → 阅读与导出。

| 编号 | 已接受的建议 | 本轮交付 |
| --- | --- | --- |
| F1 | 完善普通播放器 | 原音与 DJ 分别续听、倍速记忆、前后15秒、睡眠定时、媒体控制、手机与键盘操作 |
| F2 | 随听随记 | 播放位置记笔记、选原文创建来源笔记、引用自动附加、编辑冲突提示与准确回听 |
| F3 | 待审文章继续处理 | 补材料、编辑段落、定向 AI 修订、再次审校；原文与修订历史可比较 |
| F4 | 全库选材与多方向 | 新学习材料作为种子，召回历史材料；范围选择；同批材料支持多个不同问题；候选与成稿分别幂等 |
| F5 | 统一搜索 | 原文、文档、重点、笔记、自动文章统一检索与过滤，命中可定位来源或段落 |
| F6 | 首页和单集页调整 | 首页突出继续听、最近笔记、新文章与待处理；单集页优先播放、重点、笔记，高级设置折叠 |
| F7 | 轻量回顾 | 每周重点与笔记变化、少量主动解释问题、答后展示依据、回顾历史与再次提醒 |
| E1 | 共用播放能力 | 抽出共用传输控制、进度与媒体控制 Module，保留 DJ 独有的原音/解说状态机 |
| E2 | 改进检索与去重 | 复用 SQLite 全文索引；检索与选材共用 Interface；综合问题、主旨、材料与增量判断重复 |
| E3 | 文章反馈与版本 | 保存有用/太浅/重复/归因不准反馈；可见的偏好建议；修订、来源变化状态与双向引用 |
| E4 | 真实样本与审校模型 | 固定评测集、模型/提示版本/费用记录；可选独立审校模型；依据评测决定语义模型是否必要 |
| E5 | 安全渲染 | 原文、笔记和模型文本统一安全渲染；修正 QA 直接拼接 HTML；客户端和服务端一致验证 |

技术范围继续使用 Go、SQLite、SSR HTML 与原生 JavaScript，复用既有队列、预算、认证、CSRF、备份和来源快照。后台文章不自动承担 OwnerClaim。保持旧创作、精读、DJ 和导出路径可用。

本轮不包含原生手机 App、跨页面不断播放、完整离线音频、第三方同步、自动联网补事实和自动发布。这些不在本轮已接受建议的交付范围。

以下是本轮源码核对，运行证据继承第一轮报告；本次未重新运行应用或测试。

| QA 把答案、错误和引用片段直接拼入 `innerHTML` | 安全渲染先行；所有新页面复用经过检查的 Module |
| 仓库已有自建学习/创作 EvalSet；真实人工评分仍有待填写项 | 复用夹具并增加自动文章与检索场景，区分合成验证、真实模型运行和人工评分 |

- P0.2 抽出客户端安全文本渲染 Module：普通文本走 `textContent`；需要格式的文本仅支持受限 Markdown；引用链接由程序生成并校验协议。服务端复用安全渲染规则，模型输出不得直接变成可信 HTML。
- P0.3 修正 QA、重讲、学习对话和新文章页面涉及的文本插入路径，保留现有段落格式与引用跳转行为。
- P0.4 准备包含旧 DJ 进度、OwnerNotes、ready/needs_review/failed/在途自动文章的迁移夹具；记录各类历史数据的回填规则与幂等性。

## 5. P1：播放体验与进度

### 开发任务

- P1.1 将进度唯一键改为 `(source_type, source_id, mode)`，`mode=original|dj`。旧记录按 `plan_id` 是否为空回填，不伪造另一模式的进度。
- P1.2 扩展听播进度 Interface，返回保存成功、冲突和不存在等明确结果；校验来源存在、位置有限且非负、倍速范围和 DJ 清单身份。GET 区分没有记录与数据库错误。
- P1.3 新客户端使用服务端版本做乐观并发校验，处理同源多标签/多设备倒序更新；保留旧 `seq` 客户端的兼容入口。发生冲突时不静默覆盖较新位置，提供继续本次播放的明确动作。
- P1.4 拟新增 `playback-controller.js`，统一播放/暂停、倍速、±15秒、位置事件、保存节流、恢复与 Media Session。原音播放和 DJ 各自提供 Adapter，DJ 原音/解说切换仍由现有状态机管理。
- P1.5 倍速支持0.75、1、1.25、1.5、1.75、2；睡眠定时支持15/30/60分钟与关闭，按截止时间判断，页面进入后台后不依赖精确定时器间隔。
- P1.6 页面显示“从上次位置继续”；播放需用户动作。定位优先级为显式引用深链 → 用户选择续听 → 从头，等待元数据并处理浏览器拒绝播放。程序定位完成前不把0秒误写成新进度。
- P1.7 播放中每5秒保存，暂停、主动跳转与页面隐藏时补存；断网保留当前播放和本地待保存状态，恢复联网时遵守版本冲突规则，不承诺离页请求一定送达。
- P1.8 加入手机触控、键盘与辅助标签；用户主动浏览转录稿时暂停自动滚动，提供“跟随播放”开关。

### 文件落点与验收

`internal/store/listening_progress.go`、`internal/models/models.go`、`internal/server/listening.go`、`static/player.js`、`static/dj-player.js`、`templates/source_detail.html`、`templates/dj.html` 和新增迁移。

同一集在原音38:20、DJ第3项的两种进度可分别恢复；刷新恢复倍速；旧DJ记录迁移后可用；引用深链不被续听覆盖；多标签旧请求不能覆盖新状态。验证睡眠截止、音频不足15秒、已听完、清单换版、播放失败和网络恢复。手机媒体控制按浏览器能力降级，真实锁屏与后台播放另列真机证据。

## 6. P2：低摩擦笔记

### 开发任务

- P2.1 为笔记建立 NoteAnchor：音频时间/片段或文档段落，关联来源快照与版本。复用 Citation/Reference，不以时间戳冒充证据。
- P2.2 播放时“记一下”默认记录个人理解并捕获当下位置；选中转录片段或文档段落时默认来源笔记，预览被引用原文。界面用“来源笔记”“我的理解”，不要求填写 JSON。
- P2.3 SourceNote 必须能解析到真实来源片段；OwnerReflection 可只有位置或可选参考。转录尚未完成时允许个人笔记，不伪造来源引用。
- P2.4 DJ解说期间记录个人理解或关联真实原音；解说文本不能成为来源直接引语。界面清楚说明当前关联位置。
- P2.5 表单失败保留草稿与原锚点；保存返回后再确认成功。编辑继续使用版本校验；引用跨来源、过期快照或不匹配版本时明确提示。
- P2.6 点击笔记定位原音或原文；补齐 Markdown 导出的锚点。被文章或精读采用的笔记显示使用位置。精读已采用笔记沿用现有删除保护；自动文章已采用笔记被删除时保留历史快照并传播依据失效，旧审校不再放行下载，界面明确显示影响。
- P2.7 从功能启用时起保存不可变笔记修订，为编辑回看和每周理解变化提供依据；现有笔记只回填当前内容，不根据修订计数伪造此前正文。

### 文件落点与验收

`internal/store/owner_notes.go`、`internal/server/owner_notes.go`、`templates/source_detail.html`、文档详情模板、`internal/markdown/render.go`、拟新增 `static/owner-notes.js` 与锚点迁移。

覆盖Episode、Upload、Document；从37:42创建的笔记在保存、编辑、刷新与导出后仍定位到对应依据。来源重分析不把引用静默迁移到同名新片段；过期编辑保留用户草稿。新手操作路径不出现 JSON 输入框。

## 7. P3：文章修订与待审处理

### 数据与状态设计

知识文章保持稳定 ID，正文变为不可变 KnowledgeArticleRevision；审校绑定具体修订的内容指纹、材料快照、模型和提示版本。GenerationRun 表示一次执行，不把用户编辑、已通过修订和某个失败任务混成同一身份。上述术语先作为设计提案，实施时与 `CONTEXT.md` 核对后记录。

- 每篇文章有当前工作修订和最近通过修订；新工作稿不覆盖可阅读的旧版。
- 手动修改产生未审工作稿；保存、AI修订、再次审校均绑定预期父修订。并发修改返回冲突。
- 执行状态（排队/写作/审校/失败）与依据状态（有效/已变化/不可用）分开；依据失效不会把历史文章正文删除。
- 待审文章可以补材料、编辑或提出修改要求；单次 AI 修订最多一次写作和一次审校，仍失败时返回待审。不会无限自动反复调用。

### 开发任务

- P3.1 回填旧文章为首个修订，原样保留来源身份与状态。旧在途任务走兼容输入，提交时同时建立对应修订；不改写已有 checkpoint、模型配置或调用身份。
- P3.2 增加段落编辑、材料选择和修改说明入口；显示正文差异、材料差异与审校问题。编辑不自动变成 OwnerClaim，来源整理、个人笔记、AI综合的身份仍受校验。
- P3.3 新修订冻结材料和配置，经现有 durable queue 处理。过时任务可记录自己的结果，但不能把新工作稿或当前通过版本覆盖。
- P3.4 新增反馈：有用、太浅、重复、归因不准及可选说明，绑定被评价的修订；偏好建议单独展示，用户明确保存后才改变后续写作偏好。
- P3.5 建立修订—材料关系索引，来源或笔记变化时标记受影响修订并显示原因；生成与下载前仍做权威复查。来源/笔记页显示采用它的文章，文章可预览实际冻结依据。审校问题记录到具体段落；直接引语使用结构化引用字段并与证据逐字核对，转述与概念引号保持各自身份。
- P3.6 文章页显示各阶段结果、实际模型、用量及已知/未知费用。支持查看旧版；历史版的导出同样检查审校和依据有效性。
- P3.7 可选 `POD_REVIEW_MODEL`，默认回退 `POD_MODEL`，沿用已有POD连接；审校任务单独冻结实际模型并用对应价格计费。更换审校模型不重写旧任务。

### 文件落点与验收

现有 `store/knowledge_articles.go` 按职责分拆为修订、执行与反馈仓储；`queue/knowledge_article.go`、`provider/knowledge_article.go`、`server/knowledge_articles.go`、详情/列表模板、`config`/`selector`、来源使用查询与新增迁移。

准备正常文章、待审文章、失败任务和正在审校的工作稿。验证人工编辑、补材料后修订、两标签编辑冲突、旧任务迟到、来源变更提示、来源删除传播、双向引用、费用和版本下载。用户修改保留，旧审校不能放行新正文，未审修订不能作为已通过稿下载。已保存远端响应继续复用；显式重试保留原审计。

## 8. P4：统一检索

### 开发任务

- P4.1 建立共用 KnowledgeSearch Module。Interface 接收查询、内容类型、节目/来源、主题、时间范围和分页；返回稳定对象身份、命中片段、来源锚点与排名依据。
- P4.2 搜索覆盖原文/文档、重点、来源笔记、个人反思和最近通过的自动文章；工作稿与历史版作为明确可选过滤项，结果不把个人反思标成来源事实。
- P4.3 复用 SQLite FTS5，补充新增/编辑/删除、源失效与迁移回填的索引维护。FTS 是可重建派生数据，不保存权威正文第二份供独立修改。
- P4.4 为中文短词、词组、英文、同义问法与中英混合准备查询集。普通全文索引处理英文与完整词组；中文采用可重建的双字词索引/文字片段检索，并在候选正文校验匹配；两字查询不直接依赖trigram。全文索引失败明确可见，不把数据库错误显示成“没有结果”。
- P4.5 以分页与索引检索替代每次载入最多5000个向量再排序；限制查询长度、候选数量、片段大小和工作量。搜索GET只做本地检索，不触发收费模型。
- P4.6 对候选向量/模型做离线比较，保留本地文字检索作为默认 Adapter。真正的 embedding Adapter 使用单独配置和显式重建，不能假定现有聊天端点支持向量接口。

### 文件落点与验收

`store/semantic_search.go`、现有来源/文档/重点搜索、`server/source_handlers.go`、`templates/search.html`、新笔记/文章索引迁移与检索样本。

测试笔记中的一句话、两字中文词、完整短语、旧文章概念、跨语言问法、来源过滤和分页，删除后无残留命中。基准使用固定1万条重点/笔记/文章片段并标明机器与样本；本地索引检索目标p95≤300ms，常用检索集Recall@10≥90%。不达标时记录具体缺口并改进，不通过增加免费假结果填满列表。

## 9. P5：全库选材、多方向与去重

### 开发任务

- P5.1 引入 DiscoveryBatch 和 TopicCandidate，拆开“输入批次只发现一次”与“某个方向只成稿一次”。候选最多3个，保存问题、主旨、理由、预期增量、材料成熟度与范围。
- P5.2 自动发现用新增或实质改变的学习材料作为种子，检索历史重点和笔记；人工可指定节目、主题、时间和具体材料，也可选择探索历史材料。扫描使用可恢复游标，不一次加载全库。
- P5.3 流程改为发现问题 → 检索支持/补充/反方材料 → 冻结证据 → 判断充分性 → 写作 → 审校。选材理由与丢弃理由可查看；材料不足保留缺口，不用模型记忆补齐。
- P5.4 每个方向初始最多召回20项候选，继续限制完整材料40 KB、历史摘要8 KB和模型输出8192单位；超限按相关性和来源多样性选材，不能切断引用依据后仍宣称充分。
- P5.5 历史去重改为检索相关方向，结合问题/主旨、材料重合、受众与增量；标题文字相似只作信号。高置信度重复排除，模糊相似显示原因。续篇关联旧文章并解释新证据或新问题。
- P5.6 新批次、候选、文章与修订执行分别采用唯一身份；重复调度复用发现结果，同一方向重复点击不重收费。同一批材料的不同合格方向可分别成稿，不通过修改输入哈希绕过去重。
- P5.7 保留默认每日自动成稿准入上限1和单画像在途背压；其余候选等待后续额度，写作前重查材料与历史。人工指定方向仍接受预算与并发限制。
- P5.8 默认所有文本步骤使用已有POD连接；新增步骤各自计账、冻结模型和提示版本。若使用远端重排或embedding，单独检查来源发送策略、价格与预算，默认不开启。

### 文件落点与验收

`store/knowledge_articles.go`、拟新增发现/候选/选材仓储、`queue/knowledge_article.go` 与新增发现处理器、`provider/knowledge_article.go`、文章列表/候选模板、相关迁移。

超过40条旧材料中的相关证据可被召回；旧笔记能与新重点组合成方向；同批两个不同问题可各自成稿；同义换标题不重复出文。跨集矛盾观点得到归因，材料不足不会凑正文。覆盖并发发现、每日额度、候选等待、材料撤销、历史新增、游标恢复、模型结果未知和新旧在途任务升级。

## 10. P6：页面收敛与阅读体验

### 开发任务

- P6.1 首页顺序：继续听 → 最近笔记 → 新生成文章 → 待审/失败事项 → 本周回顾。空状态给出一个可执行入口；首页GET不触发模型。
- P6.2 主导航保留播客、笔记/重点、知识文章、搜索、回顾；新增`/notes`列表，以笔记/重点切换和来源过滤找回学习成果，底层使用P4检索Interface。创作工作台、图谱、任务和设置等放入可展开入口，保留原URL与深链。
- P6.3 单集页优先播放器、摘要/重点和笔记；转录可切换或展开；处理历史、来源策略、素材审核与权利信息放入高级区域，涉及当前处理的阻断仍直接可见。
- P6.4 文章提供连贯阅读模式与依据查看模式；段落身份保持可辨，但不把所有依据重复铺在正文中。来源预览定位冻结快照，回听明确使用哪一版音频。
- P6.5 UI错误保留用户输入，避免只落到纯错误页；后台状态更新不反复整页刷新丢失编辑/展开状态；完成提示放在站内，不新增外部消息发送。

### 验收

375px与桌面视图无横向溢出，键盘可操作，主流程不会要求填写内部ID/JSON。首页可一步继续上次收听，两步内找到最近笔记或新文章；旧工作台、DJ、精读、引用链接继续可达。前端未加载或失败时仍能阅读正文与使用基础服务端表单。

## 11. P7：每周回顾与主动解释

### 开发任务

- P7.1 保存 Owner 时区、回顾开关、每周日期和时间；后台回顾默认关闭。未设置时区时使用UTC并展示，选择时区只改变未来调度；审计时间保持UTC。
- P7.2 ReviewBatch 依据稳定周窗口收集最近学习重点、新笔记、笔记理解变化和待回看事项。个人反思保留版本变化；从此功能启用时开始记历史，不能伪造此前版本。
- P7.3 每批最多5个材料有依据的解释问题，问题与答案依据冻结并检查真实材料ID；没有材料时不生成。题目首先展示，答案依据在提交回答或主动查看后展示。
- P7.4 Owner 可填写解释、自评“能解释/部分理解/需要重看”，或选择稍后。AI可提供有依据的补充提示，不给未经校验的“掌握度”结论，也不把用户回答当成来源事实。
- P7.5 回顾答案可显式保存为个人笔记；保存新的个人理解不会覆盖来源笔记。未处理事项下次可提醒，已经处理的批次不循环重复生成。
- P7.6 手动生成与后台生成复用周窗口身份、持久队列和预算；停用不接纳新自动批次。排队结果、模型响应和用量按第一轮恢复规则保存。

### 文件落点与验收

拟新增回顾设置、批次、题目/回答仓储、队列/Provider文本步骤、`/review`页面及首页入口；复用OwnerNote版本、检索、认证与来源验证。

测试周边界、时区修改与夏令时、空材料、一周重复调度、未处理提醒、查看依据、回答保存为个人反思、来源修改和远端中断。开启回顾不自动打开文章生成；生成成本及问题数量受限。

## 12. P8：质量评估与最终门禁

### 评测安排

从P0开始维护10个可提交的自建案例：普通中文、英文/混合、历史召回、反方材料、仅个人反思、材料不足、同义重复、有增量续篇、过期依据、恶意文本。每例包含期望观点、限定条件、禁止推出的事实、应召回材料及允许的段落身份。

真实验收使用至少3集节目、至少20条笔记和2个文章主题，覆盖真实选材、成稿、待审修订、搜索和回顾。真实原文与私人笔记保存在已忽略的 `data/eval`，仓库只提交自建夹具、样本标识与不含敏感内容的报告。模型外发沿用来源既有策略与预算。

| 维度 | 自动检查/技术门槛 | 内容质量验收 |
| --- | --- | --- |
| 依据与身份 | 材料ID全部真实；直接引语校验；固定回归集中严重归因错误和失效依据放行均为0 | 人工逐条看关键主张是否充分受支持 |
| 检索 | 固定集Recall@10≥90%，记录p95与候选数量 | 真实“找回以前的理解”查询是否有用 |
| 选题与去重 | 预标注重复/续篇场景均符合预期，不能换标题骗过身份约束 | 是否存在值得回答的问题与明确增量 |
| 可读性与有用性 | 结构合法、不过度重复、尊重读者/风格设置 | 1–5分评价回答问题、忠实、具体、可读、有用；目标均分≥4且无严重事实/归因问题 |
| 播放与笔记 | 模式不互相覆盖、深链与锚点准确、并发保存安全 | 手机真实收听、锁屏操作和恢复体验 |
| 恢复与费用 | 保存过的响应不重放，不重复receipt；未知结果阻断；价格/预算正确 | 报告每个步骤用量、总费用与失败原因 |

比较当前模型、自定义 `POD_REVIEW_MODEL` 和可选语义Adapter时使用同一批输入，记录模型、提示版本、时间、用量、质量与误判；达到检索目标时可继续使用本地全文检索。不因增加一个模型就宣称质量提高。

没有真实样本、真机或人工评分时，分别标为“未验证/待评分”；技术开发可以完成，但不能把这些项记为用户实际验收通过。不能用另一轮模型自评分冒充人工评分。

### 每阶段与最终检查

- 先跑所改Module的行为测试；涉及持久状态时覆盖并发、升级、删除和失败恢复。低影响纯展示调整使用渲染/浏览器检查，不为每个标签增加实现镜像测试。

## 14. Module与Interface安排

- **Playback Module**：调用方提供原音或DJ Adapter；Module处理传输、保存、恢复、定时与媒体控制。DJ独有排序/解说切换留在现有Implementation内部，不强行统一成同一播放清单。
- **Note Module**：创建/更新接收文本、类型、Anchor与预期版本，内部解析和验证引用；页面不承担领域规则。
- **KnowledgeSearch Module**：统一查询和素材召回，使用本地全文Adapter，必要时加入经过评测的向量Adapter。没有真实变化点的职责不新增虚构接口。
- **ArticleWorkflow Module**：发现、方向成稿、修订与再审的少量操作隐藏执行身份、冻结材料、事务衔接和恢复复杂度；队列与页面跨同一Interface，不各自复制状态规则。
- **SafeRender Module**：文本、受限格式和程序生成链接分别明确输入，测试覆盖实际输出；所有相关页面复用同一规则。

模块分拆随功能落地，不另起通用Agent框架、微服务或数据库迁移。只有需要保留多种真实Adapter时才抽出对应Seam。术语和重要不可逆权衡在实施时记录到CONTEXT/ADR，计划中的表名与文件分拆是实施建议，不是已存在对象。
