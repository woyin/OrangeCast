# Jina 接入后的检索效果评测（2026-10-02）

本轮实际调用 Jina `jina-embeddings-v5-text-small`，1024维，比较项目原有 FTS 与完整 RRF 检索。检索生产代码基线06472a5未改；不是三个字符串的接口演示，也没有使用合成向量。

## 输入与边界

默认本地库只读检查：323集、0条个人笔记，尚无embedding配置/来源/向量表。未打开Store迁移默认库，也未发送其正文。实际服务可能使用另一份库；此检查不能证明远端资料状态。

使用全新临时库，助手在调用前固定20个学习/知识管理主题、20条目标资料和40条相近主题干扰资料。每个目标有原词与自然语言改写各一个查询，共40条；标注按“明确回答所问概念的目标资料”固定，而非看到排名后修改。所有文本和标注见仓库 `internal/store/testdata/jina-retrieval-fixture.json`，SHA256见report。标注由助手构造，没有Owner人工复核；这是受控测试集，不是个人真实查询或独立公开基准。

真实模型嵌入：60条笔记加1条评测来源，共61窗口；按16上限准备4个完整批次。40查询分别调用并经Reserve→Claim→Commit→Succeeded写入项目缓存，每个请求保留自己的实际用量，不拆分或编造批量费用。

## 结果

| 查询组（各20条） | FTS首条命中 | RRF首条命中 | FTS Recall@10 | RRF Recall@10 | FTS MRR@10 | RRF MRR@10 |
| --- | --- | --- | --- | --- | --- | --- |
| 原词 | 100% | 100% | 100% | 100% | 1.000 | 1.000 |
| 同义改写 | 0% | 75% | 0% | 100% | 0.000 | 0.867 |

每条只有一个固定目标，因此Recall@k等于目标是否落在前k；MRR@10为目标排名倒数，未进入前十为0。RRF在改写组找回20/20目标，但仅15/20排第一。原词组没有退步。原词与改写按20对设计，不能视为40个独立随机用户样本；改写的句式和当前FTS规则共同影响0%结果，不能概括所有用户查询。

五条首位未命中的例子：

- “读完合上书自测能帮助记忆吗”：背诵标准答案先于主动回忆，目标第2。
- “做题时轮换不同题型有什么用”：成块练习先于交错练习，目标第2。
- “给新手讲明白能检验自己是否懂了”：重读课文先于费曼学习法，目标第2。
- “只看成功案例会漏掉什么”：投资回报率、沉没成本先于幸存者偏差，目标第3。
- “保存修改历史以便回退和合并”：文件备份先于版本控制，目标第2。

这些结果表明相似向量可以找到相关主题，但仍会混淆邻近概念、反向方法和精确意图。此次没有调参后重新筛选成绩，也没有删除这些失败样本。完整逐查询指标及前三名稳定fixture ID保留在 `report.json`。

## 过程、开销与行为

- 实际44次模型请求，供应商报告输入1849 tokens；现金费用未知，没有代填价格表。模型返回身份与1024维均由现有客户端验证。
- 实测14.509s（Go test报告；含建库、网络请求、缓存任务和检查），检索阶段60对象/40样本cold p953.154ms、warm p951.994ms。cold清应用矩阵缓存，不清OS页缓存。这是小库验证，不能替代10k/50k性能门槛。
- 每条FTS与cold/warm RRF排名走项目正式Store接口，cold/warm结果逐字段相同；检索期间数据库 `total_changes()` 不变、quality identity始末一致，检索不调用模型。
- 未缓存查询降级FTS；普通语义检索仍受准入开关限制；撤回fixture来源外发权限后向量数立即归零，旧查询降级FTS。默认库、私人资料和实际语义开关保持原状。
- `real_model_embeddings=true`，`personal_corpus=false`，`human_attested_relevance=false`，`quality_gate_passed=false`。报告不是准入导入文件，不据受控成绩自动开启语义搜索。

## 复验

正常CI只运行离线fixture校验，live测试默认跳过，不使用密钥、不调用Jina。复验真实请求需要明确选择付费测试、提供已配置的环境、预先存在的报告目录：

```sh
set -a
. ./.env
set +a
CWP_JINA_LIVE_EVAL=1 \
CWP_JINA_EVAL_OUTPUT=/私有现存目录/report.json \
go test ./internal/store -run '^TestKnowledgeSemanticJinaLive$' -count=1 -timeout=10m -v
```

输入上限固定60资料、40查询、48KB原始文本；index批次额外限制8，客户端每批最多16、单条完整8192字节。没有自动重试。临时SQLite库由测试清理，报告权限0600。此次实测后仅补充输出目录前置检查及离线gold标签校验，没有修改检索实现、语料或标注，未重复付费测量。源码/fixture SHA另留清单，原始实测日志和JSON均保留。

本轮离线fixture与默认live跳过路径race通过；lint/vet及全库普通测试/覆盖率门禁见同目录日志。不将本地结果写成远端CI完成。

尚缺个人真实资料的检索标注和测量；要评估真实节目，需要明确可外发范围、建立其索引并由Owner核对目标资料。公开榜单、受控测试和个人实际效果是三种不同证据。
