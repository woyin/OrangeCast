# Jina 检索第三轮优化与对照（2026-10-02）

本轮以“不弱于纯关键词搜索”为目标。固定 60 条公开概念资料、80 条查询的对照中，最终排序有 60 条 MRR@10 严格提高、20 条满分保持、0 条退化；首位命中 79/80，前十命中 80/80。这是有限测试集的结果，不代表任意个人资料或所有新查询都更好。

## 实现与任务结果

| 任务 | 结果与验证 |
| --- | --- |
| 保留关键词优势 | 在混合检索的最多 100 条 FTS 候选中，保持有效对象的原次序；语义候选追加。属性测试覆盖 0～100 条关键词、相反向量排序、版本失效和重复候选。 |
| 防止重排损失前十召回 | 重排仅在原前十和其余候选两个集合内分别排序；关键词保护保持。显式非语义重排仍按模型分数排序。 |
| 限制极端排序分歧 | 若非关键词候选的模型最高分原排第十一或之后，保留基础排序的首个语义候选；其余按分数排序。不把供应商分数当概率。 |
| 对齐真实服务与评测 | 缓存采用和离线评测调用相同排序函数；修复评测缓存准备误用普通质量门禁路径的问题。Store 实际分页和缓存回归验证读操作不写库。 |
| 绑定版本 | 融合版本 `rrf-k60-lexical-prefix-v2`；重排策略 `rerank-top10-lexical-disagreement-guard-v3`。旧排序质量报告不再适用，缓存指纹包含新版本。 |
| 固定更广的评测 | 新增 20 条事先固定的独立查询，合计四组各 20 条；候选原次序、分数、对象 ID 和资料摘要哈希均留存。离线重放不请求 API。 |
| 费用与恢复 | 重排断点保存失败时仍尽力记录真实用量；没有断点的未知远端结果禁止自动重发。故障注入覆盖断点、回执及两者同时失败。评测脚本新增失败时也写用量账本的逻辑。 |
| HTTP 边界 | 在 CSRF 读取表单前限制重排/反馈请求大小；验证确认、恢复修订、未知结果、候选为空和超限请求。 |

保护策略有明确代价：模糊词匹配即使不如语义结果准确，也会保留在前面；原第十一名以后的正确结果不能被重排提升到前十。它保障排序边界，不宣称自动识别了所有相关答案。独立非语义重排没有上述保护。

## 验证边界

报告保留 `quality_gate_passed=false`、`personal_corpus=false`、`human_attested_relevance=false`。缺少个人笔记与人工相关性评价，不能代替正式准入；没有静默开启个人库的自动付费索引。新融合版本需要重新提交适用的质量报告。

本轮的延迟只代表 60 条小样本，不是万条/五万条容量结论。公开资料对照中的 60 次提高，也不能证明未见过的语料普遍改善。下一步真实效果取决于试用反馈，尤其是含否定、条件和相近概念的查询。
