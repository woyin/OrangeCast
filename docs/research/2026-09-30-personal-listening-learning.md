# 个人版 Podwise：围绕听与学收敛

核实日期：2026-09-30。范围为 Podwise 官方公开资料；未登录产品、未调用 API、未验证 CloudWisePod 运行行为。以下竞品事实来自本次浏览，项目方向建议属于推断。

## 官方功能与可借鉴的结构

- Podwise 提供摘要、转录、思维导图和重点，支持单集问答、库内搜索、翻译、RSS / 私有订阅源 / 音频上传，以及 Markdown 和常见笔记工具导出。[官网](https://podwise.ai/)
- 摘要 API 单独定义摘要、关键词、带时间戳与摘要的章节、思维导图；问答、takeaways、高光等字段是可选项，不能假定每集都有。[摘要 API](https://docs.podwise.ai/open-api-v1/episodes/get-episode-summary)
- Clips 从用户指定的播放点异步生成局部片段，包含文本、要点、原音起止范围和可播放媒体。这与预先生成的整集摘要或高光不同。[Clips 文档](https://docs.podwise.ai/open-api-v1/clips/overview)
- Open API 覆盖发现、处理、转录、知识产物、播放/阅读记录、问答、Clips 和导出；使用需要 Pro 或 Enterprise 权限。公开 API 不意味着其服务可自托管。[Open API 文档](https://docs.podwise.ai/open-api-v1)

## 产品建议（推断）

个人版的核心承诺建议是：**容易开始听，遇到重要内容能理解、留下笔记，并能回到原音。** 以这个闭环选择功能，不必照搬商业产品的全部产物。

| 优先级 | 能力 | 对听与学的作用 |
| --- | --- | --- |
| 首轮必需 | RSS / 音频导入、清楚的任务状态、失败重试 | 内容能持续进入，处理失败不会丢失 |
| 首轮必需 | 稳定播放器、恢复进度、章节/转录定位原音 | 每次打开能继续，学习内容可以查证 |
| 首轮必需 | 少量可信重点、收藏、个人笔记、Markdown 导出 | 从“听过”变成“留下自己的理解” |
| 后续 | 基于来源的单集问答、个人笔记搜索、简单回顾 | 帮助理解与再次使用；回顾是本项目建议 |
| 按需求 | 英文节目翻译、原音高光连播、AI 串场 | 先核实真实日常使用需求再增加成本 |
| 可暂缓 | 思维导图、多种第三方同步、跨集自动推荐、商业账号体系 | 先用章节、Markdown 和少量订阅满足个人需要 |

AI 摘要不应成为学习完成的指标。建议用三集真实节目验收：能否稳定继续听；重点是否忠实且能回听依据；能否留下个人解释，重新处理后仍保留，并在一周后找到它。本文没有把自动生成学习题或间隔复习归为 Podwise 已核实功能。

## 本轮项目证据与落点

以下本地证据由同轮主代理源码检查与定向测试提供，本研究子任务未重复执行：

- [README](../../README.md) 与 [产品目标](../product-goal.md)目前偏向学习与创作；[主导航](../../internal/server/templates/layout.html)有 12 个入口，[单集页](../../internal/server/templates/source_detail.html)在播放器之前呈现素材策略、OwnerNotes 引用 JSON、素材审核和权利约束。建议默认首页与单集页优先呈现继续听、重点和个人笔记，创作进入可选区。
- [普通播放器](../../internal/server/static/player.js)缺少倍速、续听和 MediaSession，DJ 页面已有这些能力。建议优先统一日常听播体验；这比新增 AI 产物更直接影响每天能否使用。
- 当前代码已经实现整集归并、`knowledge_dj` 自动处理深度、媒体时间驱动的 DJ；不能继续沿用 9 月 12 日笔记中关于这些功能尚缺失的结论。
- [本地语义搜索](../../internal/store/semantic_search.go)使用 192 维 `char-ngram-v1` 哈希向量；它不能直接等同于成熟的跨语言或概念级检索。先核实真实“找回自己的重点与笔记”场景，再决定是否升级。

主代理本轮针对 provider、queue、server、store 的整集归并、处理深度、DJ 状态机、听播进度和学习问答定向测试通过；未调用真实模型，也未做手机真机和真实节目听学验收。建议先跑通真实节目旅程，再考虑轻量主动回忆；图谱与跨集 DJ 可后置。代码存在、测试通过和日常听学可用仍是三种不同证据。
