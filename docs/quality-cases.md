# 私有质量案例与有界运行

质量案例是 Owner 明确接纳的版本记录，不自动等同于写作偏好。`/quality-cases` 可按原文章修订选择段落、记录四种反馈、接纳期望、修订案例版本、显式确认分类及退役。段落用内容哈希和位置二次核对；正文变化不会静默改锚。整篇有用不用伪造错误段落。

分类候选只投影冻结检索计数、容量遗漏和已有 program/owner 缺口；模型解释不是事实，全库材料是否充分不会由有界检索判定。确认分类不能重新调用诊断模型。旧案例期望、正文和材料不会被新版本覆盖。

## 显式运行一个案例

先预览（不调用供应商）：

```sh
go run ./cmd/quality-eval --db /absolute/path/owner.db --case CASE_UUID --output /private/path/run-A
```

明确运行一次写作和一次独立审校：

```sh
go run ./cmd/quality-eval --db /absolute/path/owner.db --case CASE_UUID --output /private/path/run-A --run
```

POD 连接与阶段模型读取 `.env` 和已有环境变量；环境变量优先，凭据不写进报告。最多选择一个接纳案例；10 分钟上下文限制；不会重跑发现阶段或发布文章、修改提示/生产配置。对照模型使用独立输出目录，保留同一案例内容及来源快照；不要将一个目录用于两个配置。

输出 manifest.json、write.json、review.json 和 report.json 均为私有文件，0700 目录、0600 文件。每个阶段先持久落盘 dispatched，再进行最多一次供应商调用；完成的 receipt 再读返回原结果。未知 dispatch 不自动付费重试，需人工核对旧调用后用明确新目录开启新尝试。每次读取缓存和调用前重新校验当前权限，未接纳/退役/来源禁外发案例不得运行。

receipt 保留原输出、冻结模型/提示/语料/价格指纹、实际数值 usage、耗时和失败。未知 usage 与未知成本保持明确缺失，不能当零费用；human 保持缺失，需要 Owner 自行提供五个 1–5 分数、身份和严重错误字段。严重错误单独计数，不被高平均分掩盖。报告不会自动切換模型。

## 当前验收边界

技术测试使用自建文本和 Fake 供应商。此入口尚未代替真实模型效果及人工质量验收。Owner 没有个人笔记时，不应把自建案例称作真实个人质量样本。已有私有外部下载文件不受数据库清理自动擦除；来源清理会删除/清空库内案例正文，后续运行/读取缓存经权限入口拒绝。请按个人保留需要清理已下载的私有运行目录。
